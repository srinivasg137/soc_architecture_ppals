Why won’t the PCIe Link reach L0?

Separate receiver detection, lane configuration, speed change and equalization failures.

Start with the symptom

Power is good, reset is released and Receiver Detect succeeds. Yet the expected Gen6 x16 link trains at x8, remains at a lower speed, or repeatedly enters Recovery. Those observations point to different boundaries inside training.

The useful question is: what is the last thing the link definitely proved?

Read the LTSSM as evidence

The Link Training and Status State Machine turns an electrical connection into an operational link. Detect establishes receiver presence. Polling establishes recognizable training exchange. Configuration establishes the link’s lane arrangement. Recovery handles retraining and speed related work.

Do not infer the negotiated width or speed from capabilities alone. Compare supported capability with current link status.

Separate width from speed

ObservationInvestigation
Expected x16, negotiated x8Detected lanes, connectivity and lane configuration
Expected higher speed, stable lower speedSpeed change and equalization evidence
Repeated RecoveryTraining sequence, signal quality and error correlation

Capture the sequence of states and transitions. A single snapshot can hide a repeated failure loop.

Connect hardware and software

Correlate port status with PHY observations and protocol traces. Keep link training separate from Data Link initialization and configuration enumeration. A later software discovery failure does not automatically mean the LTSSM failed.
